# 如何获取本次接口诊断

1. 更新前通过“更多 → 完整备份（含图片ZIP）”另存当前笔记，再直接覆盖安装0.3.1，不卸载。
2. 在“AI 设置”保存地址、模型和API Key并启用。未保存的输入不会用于测试。
3. 打开“更多 → 诊断记录”，点击“测试当前已保存的配置”，等待结果。测试不发送笔记，只发送一条固定短消息；会计入次数且服务商可能收费。
4. 如果连接测试成功，但整理失败，再对一条笔记点“重新整理”，等待失败后刷新诊断记录。
5. 点击“导出”保存TXT，或点击“复制”。检查错误响应中是否有不想分享的业务内容，再提供用于排查。

## 如何阅读

记录中的“阶段”说明失败发生的位置；“错误类型”提供判断线索，不等同于已经证明某个组件有故障。HTTP状态为-1表示没有取得有效状态码。网络的系统互联网验证状态不能单独证明模型接口可达。

| 错误类型 | 已取得的信息 | 需要检查 |
| --- | --- | --- |
| LOCAL_CONFIG / KEY_MISSING / CONFIG_CHANGED | 请求未完成本机配置检查，或设置在请求期间变化 | 是否保存并启用，HTTPS地址、密钥读取、是否中途暂停 |
| LOCAL_ATTACHMENT_MARKER | 消息仍含附件地址，未发出请求 | 删除未完整的图片占位符或残留附件地址后重试 |
| LOCAL_QUOTA | 本机次数检查未通过 | 每日次数上限及本地计数保存 |
| DNS | 域名未能解析 | 地址拼写、网络、DNS |
| TLS | HTTPS证书或握手失败 | 手机时间、证书链、代理 |
| CONNECT / TIMEOUT / NETWORK_IO | 连接或读写阶段失败 | 结合阶段检查网络、端口、代理或服务速度 |
| HTTP_401 / HTTP_403 | 服务已返回拒绝访问 | Key、模型权限、服务地址 |
| HTTP_404 / HTTP_405 | 服务返回未找到或不接受POST | 接口地址、模型是否存在、请求方法 |
| HTTP_400 / HTTP_422 | 服务拒绝请求参数 | 服务响应中的参数、模型兼容性说明 |
| HTTP_429 | 服务限流或额度限制 | 服务商额度及限流规则 |
| HTTP_5xx | 服务端或网关返回错误 | 服务响应、服务状态；不代表手机必然无问题 |
| HTTP_3xx | 地址要求跳转，软件未自动跟随 | 所填地址；软件不会替换为其他路径 |
| NOT_JSON | HTTP成功但返回内容不是JSON对象 | 是否网页、网关信息或其他协议 |
| SERVICE_ERROR | HTTP成功但JSON含error | 脱敏服务响应中的code/message |
| MISSING_CHOICES / EMPTY_CHOICES / INVALID_CHOICE / MISSING_CONTENT | 服务回答信封不符合预期格式 | 顶层格式、是否返回其他API协议 |
| OUTPUT_TRUNCATED | 正式操作已收到响应，但达到生成上限或模型总上下文限制 | 比较本次输出上限、completion_tokens与finish_reason；可先缩短笔记 |
| TEST_OUTPUT_LIMIT（提示类型） | 短连接测试已收到有效推理响应，但生成达到测试的64 token上限 | 接口已响应，尚未验证完整回答；继续测试一条短笔记 |
| AI_CONTENT_INVALID | 回答信封可读取，但笔记结构或来源校验失败 | 模型是否遵循要求、原文引用；连接测试不验证这些 |

## 保存范围

最近30次请求完成后记录到本机，采用原子写入。不包含请求正文和请求头，正常回答正文不记日志。失败响应最多4000字符，屏蔽当前Key、常见凭据字段以及常见正文和引用字段；未知格式仍可能带有服务商业务信息，分享前请检查。不会自动上传，也不纳入笔记JSON导出。可以单独清空诊断，笔记及AI设置不受影响。正在进行的请求完成后会产生新记录。

本版不包含系统崩溃日志或其他应用日志。更新前的No value for choices等错误没有原始响应，无法补记，需要更新后重现一次。诊断测试成功不代表后续每次请求都成功。

## 连接测试与实际整理的区别

短测试上限64 token，正式笔记整理/查找分别默认8192/4096 token，可在设置修改，二者分别记录。若短测试返回有效choices和message且finish_reason为length，即使可见正文为空，也只证明接口有推理响应，不说明笔记结果可用。日志会显示“接口连通，测试输出达上限”，不再误导用户更换模型。正式操作仍拒绝截断结果。对于WELCOME响应、鉴权错误、缺少choices等异常，测试继续报告对应问题。

## V0.3.0输入预算诊断

请求另外记录读取等待、完整序列化请求字符数、消息字符数；AI搜索记录候选篇数、正文摘录字符数及预算、片段数和回退开头数量。服务返回时记录prompt_tokens、completion_tokens、total_tokens及结束原因。字符数不是精确token估算；本机筛选和有效缓存复用没有新HTTP日志，后台整理另记请求。

图片、私有路径和附件ID不加入AI消息。服务若回显originalNoteSegments、windows或attachments等字段，会按私有正文字段隐藏，分享诊断前仍需检查未知错误格式。

## V0.3.1：响应头前失败与流式中断

- `请求数据已写出`：本机写入输出流完成，不代表服务已确认收到。
- `已取得HTTP响应头`、`HTTP状态`：未拿到状态码时为false/-1。结合`等待HTTP响应累计毫秒`，可以区分响应头前等待与读取正文时失败。
- `请求流式接收`与`实际接收方式`：短连接测试请求false；整理/搜索由设置决定。服务可能忽略stream而返回JSON，应用只解析当前响应，不新增请求。
- `首段响应正文毫秒`、`首个/最后流式事件毫秒`从本次操作开始计；没有对应数据时为-1。`流式事件数`包括DONE，`流式心跳行数`另计。
- `已收到回答字符数`、`已收到推理字符数`只记录数量；回答和推理原文不入日志。usage仅在服务实际提供时记录，不用字符数冒充token。
- `网络异常特征`只从异常/原因链中提取白名单值，例如CONNECTION_RESET、BROKEN_PIPE、SOCKET_CLOSED、CONNECTION_ABORTED、UNEXPECTED_EOF、SOCKET_TIMEOUT、UNSPECIFIED。`异常原因类型链`只含异常类名，不保存任意异常消息中的地址、Key或正文。

| 新错误类型 | 含义与下一步 |
| --- | --- |
| NETWORK_SOCKET / NETWORK_EOF | 连接报错或过早结束；先看有无响应头、片段及异常特征，不能直接判定是手机或服务端 |
| STREAM_INCOMPLETE | 流式未收到完整结束；已收到的半段内容不保存成整理结果 |
| INVALID_STREAM / STREAM_FINISH_REASON | 流式格式或结束原因不符合Chat Completions预期；可手动关闭流式检查兼容性 |
| STREAM_SERVICE_ERROR | 服务以SSE错误事件返回失败；记录有限错误代码，不保存事件全文 |
| RESPONSE_TOO_LARGE / STREAM_EVENT_TOO_LARGE / STREAM_TOO_MANY_EVENTS | 本机大小/数量保护触发；不保存部分结果 |

读取等待仍是等待下一段数据的超时，不是总生成时长承诺。短调用成功、长调用在响应头前失败时，长处理等待、服务/代理时限、网络临时中断都是可能解释；新日志可缩小范围，不能证明唯一原因。未新增自动网络重试；后台整理原有有限重试规则仍然独立生效。
