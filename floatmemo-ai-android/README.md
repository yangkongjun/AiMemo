# FloatMemo AI 安卓测试版 0.2.6

在已有 FloatMemo 安卓版上加入 AI 笔记整理。最低 Android 8.0，Java 原生界面。此包用于个人试用，不是应用商店正式发布版。

## 安装与第一次使用

1. 从 V0.2.2 / V0.2.4 / V0.2.5 更新时，使用相同包名和签名、版本代码8，直接覆盖安装。先通过“更多 → 导出全部便签（JSON）”把当前笔记另存一份；如果系统拒绝更新，请保留应用和数据，不要通过卸载来绕过。
2. 笔记只在本机应用私有数据库中，没有云同步，系统自动备份关闭。卸载或清除应用数据会删除数据库及内部迁移副本。此前独立导出的 JSON 可通过“更多 → 导入 JSON 备份”恢复；没有备份时应用无法恢复已经删除的数据。
3. 可以直接新建笔记、编辑和使用悬浮便签。内容保存在本机，未启用 AI 时不会调用模型服务。
4. 在首页打开“AI 设置”，填写可信服务提供的 **服务地址、模型 ID、API Key**。服务地址按输入原样请求，例如 `https://api-inference.modelscope.cn`；仅去除前后空白，不添加或删除路径、末尾斜杠。该地址能否处理请求取决于服务端，软件不会改用另一路径。服务需要接受标准 messages、model、stream 和 max_tokens 参数，并返回 choices/message/content 格式。
5. 阅读发送范围后勾选启用，再保存。API Key 由 Android Keystore 的 AES-GCM 密钥加密保存，不进入备份。服务可能收费，请自备服务配置；软件不内置共享密钥或免费额度。
6. 启用后新增或修改笔记将进入后台整理；已有笔记可从“更多 → 批量整理未完成笔记”加入任务。系统调度可能延迟，整理状态在笔记上显示。
7. 打开笔记卡片查看要点、已有建议、原文依据和可能相关笔记。点击“编辑原文”继续写；点击要点的“纠正这条”修改或移除。
8. 首页输入几个词先做本地文字搜索，点击“按意思用 AI 查找”再发送查询与候选片段进行相关性查找。

没有模型服务时，可以先记录和浏览；不能使用真实 AI 整理与 AI 查找。`examples/聊天笔记示例.json` 是可选的演示输入，可通过“更多 → 导入 JSON 备份”导入；它没有伪造的 AI 整理结果。

## 已实现的过程

- 保留悬浮便签、颜色、字号、透明度和原有导出功能。
- 原文、版本和整理内容分开保存；每个 AI 概括、要点、例子和已有建议都检查是否带有实际原文摘录。
- AI 标题与主主题建议、标签、背景疑问；新主题由用户确认后建立，已有分类可复用。
- 主题与标签浏览；手动主题与标签优先保留。
- 逐条纠正、移除要点、锁定人工修正、撤销最近纠正；重新整理人工修正前询问。
- 后台排队、错误显示、有限重试、日调用次数上限；原文变更和笔记删除后拒绝迟到结果。
- 本地文字搜索覆盖标题、原文、主题与标签；AI 对候选片段按意思查找并给出原文与原因。
- 本地相似内容推荐，可以标记不相关；拒绝记录进入完整备份。
- 从旧 JSON 保留原文和已有分类迁移到 SQLite；保留原 JSON 及首次升级备份。
- 完整 JSON 导入导出，包含原文、整理、纠正记录和来源版本。冲突保留双方；相同备份重复导入会按导入记录和当前内容跳过。被删除的记录允许从同一备份恢复。

## 这版的明确边界

这是可构建的首版原型，不等同于需求文档全部验收完成。完整对应表见 `REQUIREMENT_STATUS.md`。

- 主题当前是平面文件夹，尚无三级结构、标签同义词合并及全局分类规则。
- “可能相关”使用本地标签与措辞相似度，不是 AI 推理出的因果关系。被拒绝的关联在该笔记上隐藏。
- AI 搜索每次最多检查30条候选笔记，每条正文前1400个 UTF-16 字符；候选先按措辞重合选取。界面说明覆盖范围。不是全库向量语义检索，可能漏掉较早或较深处的内容。
- 超过1万字符的笔记按段整理，每段单独请求，逐段概括；尚无全文综合概括。单篇上限12万字符，超过时明确报错，原文照常保存。
- 原文摘录存在只能证明来源有效，**不能证明概括一定忠实**，仍需用真实笔记评价。
- 默认每日最多20次请求，可设置1至500。失败和重试也计数。没有费用估算、token 统计或付费账户；服务费用由服务商收取。
- 系统停止任务后可以恢复排队，应用重新打开会恢复处理中状态；不承诺关机后自动整理或准确开始时刻。
- 备份导入上限20MB，未做大规模笔记性能验收。数据库读取和短写入仍使用简化实现。
- 未实现云同步、语音、OCR、自动联网扩写和专题跨笔记总结。
- 尚无真机或模拟器安装、触摸和中文输入验证；未使用真实 API Key 联调任何模型，不承诺所有兼容服务都可用。

## 数据与隐私

AI 默认关闭。启用后，自动整理会发送正文、原标题和已有主题名称；AI 查找会发送查询、候选标题标签及正文片段。没有自动读取其他应用、自动抓取网页或与外部工具交互的功能。

暂停或清除配置后不再主动开始新的网络请求；已经发送的内容无法撤回，在途结果在设置版本变化后丢弃。服务商的数据留存政策需你自行确认。原始笔记、模型结果和独立导出备份不是端到端加密云库，请妥善保管导出文件。

## 构建与验证

需要 JDK17、Android SDK Platform35 和 Build Tools35.0.0。Gradle Wrapper8.9 与 Android Gradle Plugin8.7.3 沿用原版。

```bash
./gradlew assembleDebug testDebugUnitTest lintDebug
```

Windows 使用 `gradlew.bat`。单元测试使用 JUnit4 和 `app/test-libs/json-20240303.jar`，JSON-java 的许可位于同目录；JSON-java 只用于 JVM 测试，不打入应用运行依赖。

测试结果、未测项目和 APK 校验值见 `VALIDATION.md`。源码包不含开发机路径、构建缓存或签名私钥。

## 实现入口

- `NoteRepository`：SQLite 存储、原文版本、纠正、导入与迁移。
- `AiConfig`：授权开关、接口配置、Keystore 凭据与调用上限。
- `AiJobService`：安卓后台整理任务。
- `AiClient` 与 `AiDocument`：模型调用、分段、结构与原文引用检查。
- `SearchEngine`：本地搜索、候选排序和相似内容推荐。
- `AiDetailActivity`：要点、依据、纠正、主题标签与相关笔记。
- `BrowseActivity` 与 `AiSettingsActivity`：浏览、待确认与配置。

本项目基于先前提供的 FloatMemo 安卓重写项目继续开发；macOS 原项目为 https://github.com/DevAutoFarm/floatmemo 。

## 0.2.2 安装包修复

取消独立修复版包名，恢复普通包名和应用名称。修正0.2.1手动打包时将 resources.arsc 误压缩的问题；资源表必须以未压缩形式存放，并在签名后的 APK 中保持4字节对齐。

构建后除了签名校验，还运行安装结构检查：

```bash
python3 tools/check_apk.py path/to/app.apk
```

该检查包含资源压缩方式、资源本地数据偏移对齐、必需文件、二进制清单和 ZIP CRC。它不能替代实际设备安装验证。

## 0.2.4 地址处理修正

移除自动补全请求路径。HTTPS 地址校验不改变所填地址，实际 POST 请求也使用该值，且不自动跟随重定向。现有设置不会猜测还原：如果之前已经保存了补全后的地址，请重新填写想使用的地址。数据结构和笔记读写流程未修改。

## 0.2.5 诊断记录

首页“更多 → 诊断记录”或“AI 设置 → 诊断记录 / 测试已保存配置”可查看、刷新、复制、导出及清空。整理失败的笔记详情也提供入口。只记录更新后的请求，之前的错误不能补记。

诊断测试仅发送固定短消息，使用已保存且启用的地址、模型和密钥，计入每日请求次数，可能产生服务商费用。诊断继续按所填地址直接请求，不追加路径或自动跳转。测试成功仅代表回答通道可用，不能证明笔记内容质量。

本机最多保留30次请求的时间、环境、地址、模型、失败阶段、HTTP状态、响应类型、错误分类及耗时。失败时保留限长且脱敏的服务响应片段；不保存请求头或请求正文，不保存正常模型回答正文。错误响应仍可能包含服务商返回的业务信息，分享前请检查。记录不自动上传、不进入笔记JSON备份，卸载会删除。详见 DIAGNOSTICS.md。

## 0.2.6 短测试输出上限的判断修正

固定短测试仍使用64 token上限，但有效的推理响应若finish_reason为length，会显示“接口连通，测试输出达上限”，并明确尚未验证完整回答，不再要求换模型。诊断同时显示本次请求输出上限、finish_reason及服务返回的token用量。正常笔记整理和AI查找继续使用3000 token上限，截断结果仍不作为完整笔记结果保存。测试不会自动增加额度、重复请求或改地址。
