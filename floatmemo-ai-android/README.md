# FloatMemo AI 安卓 V0.3.2

当前包名 `io.github.floatmemo.android`，versionCode 11；Android 8.0及以上，Java原生界面。包含生成预算配置、本机图文、完整备份、有限候选搜索和流式接收。

## V0.3.2标签与主题卡片列表

在“主题标签”点击一个标签或主题，进入单独的笔记列表页。每条笔记有独立白色圆角卡片、细边框与间距，显示最多两行标题、三行原文预览、标签、主题、最近更新时间和图片数量；长内容省略显示，点整张卡片进入原有详情页。

列表按最近更新排序，顶部显示当前标签/主题与数量，返回按钮或系统返回回到上一级。笔记修改标签、主题或被删除后，重新进入或返回列表会刷新；空列表有明确提示。列表使用原生ListView复用卡片，并按可见笔记标识与偏移保存/恢复滚动位置。

预览只读本地原文，图片标记不作为文字显示，不请求模型，不修改数据库、媒体、AI预算或用户设置。标签和主题名称按完整值筛选，标签不做模糊子串匹配。实现与设备待测项目见[本次交付说明](../docs/releases/V0_3_2.md)。

## V0.3.1接收与诊断

整理和AI搜索默认启用流式接收；原有token、等待、地址、模型及密钥设置保留。AI设置可关闭“流式接收长回答”，恢复普通接收。短连接测试请求仍为非流式、64 token，不能证明长回答也一定可用。

服务逐段返回时，应用逐段接收，在完整结束、结构与原文校验通过后再保存。推理内容只计字符数，不保存正文。不完整、断流、length截断及来源错误继续拒收。服务忽略stream并返回普通JSON时，直接读取同一个响应，不补发请求、不自动切换重试。

诊断增加请求已写出/是否取得HTTP响应头、响应头等待时间、实际JSON/SSE方式、首段正文/事件时间、事件数、已收回答/推理字符数，以及连接重置/套接字关闭等白名单异常特征。不会保存任意异常原文、半段回答或推理正文。详见[本次交付说明](../docs/releases/V0_3_1.md)。

流式能否减轻断连取决于模型、服务与代理是否及时转发数据，不保证绕过服务时限或消除所有网络问题。

## 更新与第一次使用

先在旧版“更多”导出笔记备份，再使用原签名的V0.3.2直接覆盖安装。不要卸载或清除应用数据来绕过更新错误；应用私有笔记与图片没有云同步，卸载会删除它们。新版本完整备份入口为“更多 → 完整备份（含图片 ZIP）”。保留旧备份，不承诺旧版应用可以读取新媒体数据。

AI设置保留原有地址、模型、密钥和启用状态。只按填写的HTTPS地址发送，不自动补路径、跳转或换模型。新预算字段缺省为：整理8192 token、搜索4096 token、读取等待120秒、候选最多10篇、正文摘录合计12000字符。都可在设置修改；应用范围不代表服务商支持，上限不等于实际消耗或总上下文容量。

## 本版新增的操作

- **扩大生成预算**：在AI设置分别填写整理、搜索的上限和读取等待。改变设置不会重跑全部已完成笔记。短诊断仍为64 token，正式截断结果不保存，不自动加量续写。
- **插入图片**：完整编辑页点“插图”，系统选择JPEG、PNG或静态WebP。复制成功后在光标处插入占位符；预览显示图片，点图放大。原图保存在应用私有目录，删除相册原件不影响副本。悬浮窗可以预览，并通过“插图↗”进入完整编辑页。
- **完整备份**：ZIP含笔记、主题、历史、纠正和原图片。导入前检查路径、CRC、大小及SHA-256；冲突保留，重复导入跳过相同记录，也能修复缺失原图。旧JSON继续导入；“仅导出文字及元数据（JSON）”不含图片文件，不能代替完整备份。
- **控制搜索成本**：输入时本地搜索不调用API；点AI查找后先按当前范围本地筛选，再截取命中附近。可以明确改查全部笔记。每篇最多3个不重叠片段、1200字符，并受合计预算限制。无正文直接命中时回退开头，诊断记录回退数量。
- **避免重复搜索**：一次搜索最多一个HTTP请求，不自动补搜或重试；重复点击或界面重建复用正在进行的搜索。相同条件下复用有效缓存（最多20项、约8MiB、5分钟；进程退出或淘汰后失效）。笔记、标签、主题、范围和AI设置改变后不用旧结果。

详细操作、可自行修改的位置和边界见 [V0.3.0开发与使用补充](../docs/developer/V0_3_0_Usage_And_Development.md)。原来的笔记要点、主题标签浏览、人工纠正锁定及后台队列继续保留。

## 图片与数据边界

单张20MiB、每篇20个图片引用、原文件合计100MiB；边长最多40000且不超过1亿像素。预览最长边约320像素，查看图最长边约2048像素采样，原文件不改写。不做OCR、AI识图、拍照或剪贴板粘图；图片文件、附件标识和私有路径不交给模型。只有图片的笔记不发整理请求，可自行补充文字说明。

只增删图片时，如果文字、标题和引用依据仍有效，保留AI结果，不重复排队。原文引用不能跨过图片；插图恰好切断旧引用时标记依据已改变，允许手动重新整理。旧结果仅在原版本和原文引用有效时迁移文字指纹。未引用的旧图片仅在后续启动时、超过24小时且当前笔记/历史/纠正都未引用才清理。

完整ZIP上限500MiB、展开后1GiB；文字及历史JSON上限20MiB，单次最多10000条当前笔记。图片流式处理，但文字JSON及编辑界面仍为内存数据，不能把上限当成低内存手机的性能保证。恢复采用暂存、校验、文件恢复记录和数据库事务；写入新原图后才提交数据，不覆盖同标识的不同原图。

## 搜索与整理边界

本版不是全库向量语义检索。本地措辞候选可能漏掉完全不同表述的记录，AI只检查已发送片段。搜索原文引用必须来自同一笔记的单个实际发送片段，并可回到原文位置。正文字符预算与完整请求token数不是同一个概念；标题、标签、查询及JSON开销另有长度限制，诊断记录完整请求字符数和服务返回用量。

3000字常规笔记通常仍是一段；保持约10000字符分段、单篇12万文字字符上限，更长笔记按段请求，无全文综合概括。后台整理仍沿用既有有限暂态重试，和用户点击的单次AI搜索分开记账。模型是否忠实、是否找得准，需要真实笔记评价。

## 构建与验证

JDK17、SDK35、Build Tools35.0.0、Gradle8.9、AGP8.7.3：

```bash
./gradlew assembleDebug testDebugUnitTest lintDebug
```

Windows使用 `gradlew.bat`。默认Gradle debug签名不能保证覆盖当前手机安装包；使用用户私下保存的原签名继续升级。Linux手工构建入口见 [android-build-fix](../android-build-fix/README.md)，签名密码从本机环境变量读取。

本版验证与未测项目见 [VALIDATION.md](VALIDATION.md)。源码不含密钥、私钥、个人笔记、APK、SDK及构建缓存。JSON-java仅用于JVM测试，许可见app/test-libs。

本项目在先前FloatMemo安卓重写版本上继续开发；原macOS参考项目为 https://github.com/DevAutoFarm/floatmemo 。
