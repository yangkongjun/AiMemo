# V0.3.1：长回答接收兼容与断连诊断

版本0.3.1-ai-preview、versionCode 10，日期2026-10-27。在V0.3.0的图文、预算与搜索逻辑上改进接收层，沿用原包名和证书。更新不需要卸载，原笔记、图片、模型地址、Key和用户保存的token预算保留。

## 问题与证据边界

短调用成功，只说明该配置当时能完成短响应。较长调用在取得HTTP状态码前连接报错，可能涉及较长生成等待、服务/代理时限或暂态网络问题；不能仅凭这一组合认定某一端故障，也不能认定token超限。本次没有复现用户实际服务的断连，不声称已经证明唯一根因或保证消除故障。

## 改变了什么

- 整理与AI搜索默认请求`stream=true`；AI设置新增可关闭的“流式接收长回答”。短连接测试请求仍非流式、64 token。原生成预算不自动调小或调大。
- ResponseReader读取同一个HTTP响应，识别普通JSON或Chat Completions SSE。服务忽略stream返回JSON时直接解析当前响应；不再发一遍请求，不自动切回普通模式或重连。
- SSE逐段接收可见文字，只统计推理字符数量；完整结束后转成原有回答信封，再做截断、JSON、原文引用、版本/代次及人工锁定检查。断流、无正常结束、冲突结束原因及length均不作为完整笔记结果保存。
- 请求使用明确Content-Length并保持禁止重定向。没有新增网络重试；后台整理既有有限暂态重试规则仍独立适用，AI搜索保持一次应用请求。
- 诊断增加请求是否写出、是否取得响应头、等待响应头耗时、实际JSON/SSE方式、首段/事件时间、事件/心跳数和已收可见/推理字符数。网络异常只记录白名单特征及原因类名链，不保存任意异常消息、半段回答或推理原文。
- 为防SSE包装开销误触发普通响应上限，分别限制单事件256Ki字符、可见正文按片段UTF-8计数2MiB、总传输32MiB和100000个数据事件。

当服务/代理及时转发分段时，有机会减少长期无数据导致的断连；如果模型首次响应仍很慢或网关缓冲SSE、强制限制总时长，这个改动也无法保证解决。读取等待仍是单次读等待，不是总任务时长承诺。

## 更新后怎么检查

先从旧版导出完整备份，直接覆盖安装。AI设置确认“流式接收长回答”开启，保留原token预算后对同一条需要整理的笔记手动重试一次。若失败，提供该次记录的请求流式开关、阶段、HTTP状态、是否取得响应头、实际接收方式、事件数和网络异常特征即可继续定位；不用分享Key或笔记正文。

服务明确不支持流式时可手动关闭；切换不会自动调用模型，下一次明确操作才使用新配置。流式用量取决于服务返回usage，未提供时不伪造统计。
